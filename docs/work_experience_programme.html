Giving Back

Work Experience Programme

Real projects. Real work. Something concrete to take into your career.

This programme gives participants a genuine piece of real-world experience in data, statistics, analytics, and research — completing a focused, consulting-style project over approximately one week (full-time equivalent).

These are not toy exercises. They reflect the kind of work that arises in practice. The goal is to give you something concrete, credible, and explainable to take forward into interviews, applications, and future work.

The default duration is one week full-time equivalent. If you are a part-time student or have other commitments, this can be spread over two weeks — just mention it in your application.

Open to more than students. While this programme is primarily aimed at university students, we welcome applications from anyone at an early stage of their data career — including recent graduates and self-taught individuals looking to build practical experience.

The Process

How It Works

01

Apply via LinkedIn

Apply through our LinkedIn job posting. Include your background, project preference, and GitHub profile.

02

Onboarding

Join a cohort intro call, then have a one-to-one onboarding call to agree your project scope and approach.

03

Complete the Project

Work independently over approximately one week. Daily stand-ups and a mid-week check-in keep things on track.

04

Debrief & Certificate

A final debrief call with structured feedback. On completion, receive your certificate and a portfolio-ready project.

On Completion

  • A completion certificate from The Data Guru Ltd
  • A portfolio-ready project you can show to employers
  • Something concrete and explainable on your CV or LinkedIn profile
  • Structured feedback from an experienced data professional
  • Experience working to a real consulting-style brief

Structure & Support

How We'll Stay in Touch

We keep contact structured but light — enough to support you without becoming overwhelming.

Cohort Intro Call

All participants together. We introduce the programme, answer questions, and give everyone a chance to meet each other.

Individual Onboarding

A one-to-one call to agree the scope and approach for your specific project. This is where we align on what a strong submission looks like.

Daily Stand-up

A brief (~10 min) daily check-in — video call or async message, whichever works best for you. Format is flexible to accommodate time zones and schedules.

Mid-week Check-in

A brief individual catch-up to make sure things are on track and to unblock anything that's come up.

Final Debrief

A one-to-one closing call with structured feedback on your submission. This is where we review your work and discuss what you've learned.

Open Door

Outside scheduled touchpoints, you're always welcome to reach out if you're stuck or have questions. We're approachable.

Note on format: Stand-ups and check-ins can be video calls or async written updates — we'll agree what works best for each participant during onboarding.

What We Expect

Expectations

Independence

You are expected to complete the work independently. This is about demonstrating what you can do.

AI Tools

Use of AI tools is allowed — but you must be able to explain and justify everything you submit. The work must be yours.

Quality over Perfection

The focus is on clarity, structure, completeness, and good judgement — not on producing perfect work.

Language preference: For coding projects, we strongly prefer R or Python. If you have a strong reason to use a different language, please mention it in your application and we'll discuss it.

For Coding Projects

Git & GitHub

Git and GitHub are essential for all coding projects. If you haven't used them before, here's a quick-start guide.

Getting Started with Git

Git is the industry-standard version control tool. All coding submissions must be submitted via a GitHub repository. If you're new to it, these are the only commands you need for this programme:

Step 01

Install & Configure

Download Git from git-scm.com. Then set your identity:

git config --global user.name "Your Name" git config --global user.email "you@email.com"
Step 02

Create a Repository

On GitHub, create a new repo. Then clone it locally:

git clone https://github.com/you/repo-name
Step 03

Save & Push Your Work

The three commands you'll use every day:

git add . git commit -m "describe your change" git push origin main
Application requirement for coding projects: Before applying, please create a GitHub repository named something like "the-data-guru-work-experience" containing at least one script that demonstrates the basics: reading data from disk, a simple manipulation or summary, a plot, and writing output back to disk. Include a link to this repo in your application. This helps us confirm you have the foundational skills for a coding project — it doesn't need to be impressive, just functional and your own work.

Choose Your Project

Available Projects

Projects vary in nature and difficulty. Read each description carefully before choosing.

Project 01

Data Quality Tool

Intermediate

In most real-world data projects, the first step is to assess data quality. Build a tool that scans a dataset and produces a structured data quality report.

Objective — build a tool that produces:
  • Missing data summary
  • Variable types and distributions
  • Outlier and duplicate detection
  • Basic relationships (eg., correlations)
Deliverables
  • Code in Python or R
  • Output report (HTML, PDF, or notebook)
  • README explaining what it does and how to run it
  • GitHub repository
⭐ Optional Extensions

Not required — for those who want to go further:

  • Add automated visualisations (histograms, correlation heatmap)
  • Support multiple file formats (Excel, JSON, Parquet)
  • Add a scoring system that rates overall dataset quality
  • Package it as a reusable library with a CLI interface
Coding
Project 02

Data Anonymisation Tool

Intermediate

Real-world data is often sensitive and cannot be shared directly. Build a rule-based tool to de-identify a dataset while preserving its analytical value.

Objective — implement techniques including:
  • Removal of direct identifiers
  • Generalisation (eg., age bands, date rounding)
  • Pseudonymisation (eg., hashed identifiers)
Deliverables
  • Code in Python or R
  • Example input and anonymised output
  • README describing approach, assumptions, and limitations
  • GitHub repository
⭐ Optional Extensions

Not required — for those who want to go further:

  • Implement k-anonymity checking
  • Add a risk assessment report alongside the anonymised output
  • Support configurable rules via a config file
  • Add a reversibility mechanism for authorised users (pseudonymisation)
Coding
Project 03

Simple Data Dashboard

Most Technical

Communicating data clearly is as important as analysing it. Build an interactive dashboard that lets a user explore a dataset without writing any code.

Objective — dashboard should allow users to:
  • Explore a dataset interactively
  • View summary statistics
  • Apply basic filters
  • Visualise key variables
Deliverables
  • A working dashboard (Streamlit, Shiny, or similar)
  • Code and README explaining usage and how to run it
  • GitHub repository
⭐ Optional Extensions

Not required — for those who want to go further:

  • Allow the user to upload their own dataset
  • Add a statistical summary section with significance tests
  • Deploy the dashboard publicly (eg., Streamlit Cloud or shinyapps.io)
  • Add export functionality (download filtered data or charts)
Coding
Project 04

Mini Research Paper

Most Accessible

Not all data work is coding. Produce a structured, evidence-based piece of writing (1,500–3,000 words) on a relevant topic in data science or statistics.

Example Topics
  • Risks of data leakage in machine learning
  • Missing data in practice: when does it matter?
  • Explainability vs. performance in predictive modelling
  • Collider bias in applied settings
Deliverables
  • Written piece in Markdown, PDF, or Word
  • A references list (minimum 5 sources)
  • Clear structure: introduction, concepts, examples, limitations, conclusion
⭐ Optional Extensions

Not required — for those who want to go further:

  • Include a worked example with real or simulated data
  • Produce a short accompanying code notebook illustrating a key concept
  • Extend to a longer, more comprehensive treatment (4,000–5,000 words)
  • Submit it to a student journal or post it publicly on a blog or GitHub
